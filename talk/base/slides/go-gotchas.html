Three things that catch you out in Go

13:15 to 14:00. No clicks. Style: text scramble, like a departures board. The three rows decode one after another, a new one every 1.6 seconds, so pace one sentence per row; if you are behind, let it run and go to the demo. One: map iteration again, because it is the determinism bug Go developers actually hit. Two: StepAsync, InvokeAsync and Go queue their start even if never awaited, but the invocation answers with the handler's outcome and does not wait, so a body may not run to completion. The JavaScript SDK behaves the same way, so this is a gotcha, not a difference. Three: handler options are read once at program start, so Start and Wrap panic on an invalid one: a bad option fails the cold start, not a request. Map order and handler options are real differences from the other SDKs.
