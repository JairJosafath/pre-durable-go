Durable Execution Telemetry

The panel plays once, about seven seconds: four sheets drop in, one log stream per invocation, then they collapse into a single orange sheet, the execution record, and its summary lists itself beside it. The figures in that summary are illustrative. The point: Lambda writes a log stream per invocation, so one execution's history is scattered across streams, and four tools put it back together. Logging answers what the code printed in each invocation. ctx.Logger() and the step context's Logger() return a standard *slog.Logger; by default replayed records are suppressed, so each line appears once. Bring your own slog.Handler with durable.WithLogHandler, or emit replayed records tagged replay=true with durable.WithReplayLogMode(durable.ReplayLogModeEmit). Plugins are the extension point the other tools build on: a durable.Plugin is a struct of optional hook functions. OpenTelemetry gives spans. Telemetry answers whole-execution questions (which step failed, how many attempts, how long) as ordinary queries, because one record describes one execution; there is also an MCP server that gives an agent read-only access to those records. Go caveats: the Go record type is telemetry.Record with slightly different field names, and Go has no OTLP exporter.
