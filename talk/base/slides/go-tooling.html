durabletest: local runner

r := durabletest.NewLocalRunner(handler)
result, err := r.RunUntilComplete(41)
got, err := durabletest.ResultAs[int](result)

  • Runs in process: no network, no AWS credentials
  • Completes pending timers and step retries between invocations
  • Rejects what the service rejects, such as a step result over 262,144 bytes
  • SendCallbackSuccess resolves a callback the handler is blocked on
12:15 to 13:15. No clicks: the top panel plays once, about eight seconds. It types durablelint ./... and a scan line runs down a deliberately bad handler; four lines get a pink underline and their rule appears on the right. Line 2, time.Now() in orchestration code: durablenondeterminism. Line 3, a go statement around a durable operation: durablegoroutine. Line 6, writing to a captured variable inside a step: durableclosure. Line 7, an operation created inside a step body: durablenestedop. The fifth analyzer, durablechildctx, flags a captured context used inside a function that receives its own. The findings shown illustrate what each rule is for; they are not captured output from a real run. durablelint lives in its own module (github.com/aws/aws-durable-execution-sdk-go/analysis, Go 1.25 or later); install with go install .../analysis/cmd/durablelint@latest. It also runs as go vet -vettool=$(which durablelint) ./... and loads into golangci-lint v2 as a module plugin. Suppress one finding with a //durable:ignore comment. durabletest is in the main module under durable/durabletest. RunUntilComplete invokes the handler as many times as the execution needs, so a handler with a one-hour Wait is an ordinary unit test. result.Operations lists every recorded operation, so a test can assert a step ran once across replays. NewCloudRunner runs the same assertions against a deployed function.
