PrimeDrive, the Go Durable way

One durable function replaces the Step Functions state machine, its trigger function and the ASL definition.

Show the video of the app first, then this slide. No clicks; the diagram plays once, about twelve seconds, in four beats. One, upload: the browser asks the API for a presigned URL (the presigner function) and puts the file straight into S3. Two, the pipeline: S3 invokes the durable function through its live alias, with no trigger function in between. It registers the upload, runs the Rekognition steps while a plain Lambda makes the thumbnail, and writes to DynamoDB. Three, review: when the analysis gives a reason, the execution suspends. POST /reviews reaches the reviewer function, which reads the callback ID from the file record and calls SendDurableExecutionCallbackSuccess; the same execution resumes. Four, search: GET /query, /files and /labels are API Gateway integrations straight onto DynamoDB, with no function at all. Not drawn: Cognito signs users in and API Gateway checks the token on every route; thumbnails go to a second bucket. Infrastructure facts if asked, from infra/lib/constructs/upload-pipeline.ts: durableConfig is the only difference from a regular function; execution timeout is the 24 hour review timeout plus one hour, retention 14 days, and one invocation is limited to one minute.
