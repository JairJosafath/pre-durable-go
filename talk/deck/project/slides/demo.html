14:00 to 19:00, five minutes. The operation above each stage is taken from the CDK stack; rename to match the handler in cmd/pipeline once it is written. Script: 1) Infra, 45 seconds. Open infra/lib/constructs/upload-pipeline.ts. durableConfig is the only infrastructure difference between a durable function and a regular one: execution timeout is the 24 hour review timeout plus one hour, retention is 14 days, while the function timeout for a single invocation is one minute. A durable function is always invoked through a version or alias, here "live", so an execution that started on one version keeps replaying on that version even if you deploy while it waits. S3 invokes the alias directly for keys under users/. 2) Upload a photo in the frontend (presigned URL). 3) Open the execution: the analysis steps are checkpointed and it is waiting at the review callback. Point out that no invocation is running. 4) Approve with POST /reviews. The reviewer Lambda calls SendDurableExecutionCallbackSuccess (it is the only function allowed to). The same execution resumes: replay skips the analysis, then durable.Invoke calls the thumbnailer and the index step writes one item per label. 5) Search with GET /query?index=<label> and show the photo. 6) If time allows, say what happens on reject or after 24 hours without a decision: the upload is deleted. Mention that label items are keyed by label and object, so the index step is safe to retry and replay. Keep a finished execution open in another tab in case the live one misbehaves.
