Five things that differ in Go

13:15 to 14:00. No clicks. Style: text scramble, like a departures board. The five rows decode one after another, a new one every 1.6 seconds, so pace one sentence per row; if you are behind, let it run and go to the demo. One: in Go a zero MaxAttempts means "use the default" (3 for RetryConfig, 6 for LinearRetryConfig, 60 for WaitConfig); porting maxAttempts: 1 from JavaScript means durable.NoRetry(). Also note the unconfigured step default is ExponentialBackoff() with 6 attempts, while a RetryConfig you build yourself defaults to 3. Two: map iteration again, because it is the determinism bug Go developers actually hit. Three: callback results pass through RawSerdes, so the type parameter should be string, []byte or json.RawMessage unless you pass WithCallbackSerdes(durable.JSONSerdes). Four: StepAsync, InvokeAsync and Go queue their start even if never awaited, but the invocation answers with the handler's outcome and does not wait, so a body may not run to completion. Five: handler options are read once at program start, so Start and Wrap panic on an invalid one: a bad option fails the cold start, not a request.
