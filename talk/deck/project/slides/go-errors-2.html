Match on ErrorType, not on your own type

receipt, err := durable.Step(ctx, "charge", charge,
    durable.WithRetry(durable.NoRetry()))

var stepErr *durable.StepError
switch {
case err == nil:
    return receipt, nil
case errors.As(err, &stepErr) &&
    stepErr.ErrorType == "CardDeclinedError":
    return "declined", nil
default:
    return "", err // may be the suspension signal
}

Rebuilt from the checkpoint

A typed failure carries the recorded ErrorType and Message, not your original error value.

errors.As finds the SDK type

*durable.StepError, or *durable.OperationError for any operation.

Sentinels use errors.Is

ErrCallbackTimedOut, ErrWrongGoroutine, ErrWrongContext.

The pattern in code. A typed failure is rebuilt from the checkpoint, identically on the first run and on replay, so errors.As against your own CardDeclinedError will not match; compare stepErr.ErrorType. ErrorType is "Error" for errors.New and fmt.Errorf, and the Go type name otherwise. The default branch returns err untouched, which is what lets the suspension signal through. When the handler itself returns an error, the execution settles FAILED.
